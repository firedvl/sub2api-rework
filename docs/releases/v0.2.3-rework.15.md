# v0.2.3-rework.15 — Claude automatic warm-up

Claude OAuth parent accounts can opt into automatic warm-up from the account editor or bulk edit. The gateway waits for an idle or expired five-hour window, sends the existing connection test’s small request, and confirms the new window from upstream headers or fresh usage data. It saves Claude’s actual reset time for the account countdown and reports completion only after confirmation.

Delayed confirmation is checked again without another request. Retrying inference requires a fresh idle quota observation and a durable ten-minute minimum between attempts. Active windows wait until the provider’s reset, and usage API retry boundaries are respected. Claude warm-up is disabled by default and independent of the OpenAI master switch. API keys and setup tokens are unsupported. Requests consume subscription quota and may incur extra usage when enabled upstream.

This release keeps schema 252, supported schemas 239–252, minimum updater 1.1.6, stable channel and manual update policy. Install through the verified host updater. See [Claude warm-up](../CLAUDE_WARMUP.md) for configuration and behavior.

Validation includes focused backend race tests, PostgreSQL claim and filter integration tests, frontend unit tests and TypeScript, and mobile/desktop browser tests covering configuration and a decreasing countdown. No live Claude inference canary was performed during development.
