# v0.2.3-rework.13 — M23

Claude Code can use one downstream Sub2API key and `https://gateway.fdvl.net/anthropic-api` to route requests among authorized Anthropic API-key accounts in one Anthropic group. The canonical scheduler applies priority, effective load, concurrency slots, least-recent use and randomized ties. Model eligibility, credential/group revalidation, cooldown and bounded failover remain enforced. Affinity now includes the authenticated downstream key, and diagnostics omit raw session identities. Streaming output is never replayed after emission; subscription OAuth is never a fallback.

Manual Refresh now actively updates eligible Claude OAuth usage; Auto Refresh queries when the three-minute successful-observation cache permits. Concurrent callers share observations, fleet work stays bounded, and provider backoff and 429 Retry-After apply. Five-hour and weekly windows keep separate observation times; partial responses preserve other windows, and stale/error states remain visible. Capacity and Technical share observations on desktop and mobile. Dedicated Query remains optional. SetupToken stays passive; API-key accounts have no subscription-window query.

Official Claude Code 2.1.300 passed synthetic real-handler contracts for streaming, tools/results, Read/Edit, resume, model switching, status, cancellation and pre-output failover. Raw HTTP verified token counting against the same handler. These are bounded loopback contracts; live provider and hours-long session acceptance remain outstanding. See the [account guide](../CLAUDE_CODE_ACCOUNTS.md) for separate API-gateway and native subscription profiles.

Anthropic API keys are billed separately from Claude subscriptions. Keys in one Anthropic organization share its provider limits; adding keys does not multiply those limits. Gateway limits are soft, and usage-observation completeness does not prove final provider billing. Production has no Anthropic API-key pool. Real multi-account provider/billing acceptance needs separately authorized account setup, spending controls and paid canaries. This release does not authorize subscription OAuth pooling. The Claude native warm-up companion remains disabled.

The release transition is `.12`/schema 252 → `.13`/schema 252, with supported schemas 239–252 and minimum updater 1.1.6. There is no new migration or implicit schema change. Upstream remains v0.2.14 at `0363b8cdba8cec3e2ba4b2dbd49c4481143fa55d`; stable channel and manual policy remain.

A later authorized install must verify immutable image/provenance, quiesce writers, verify its backup and require exact schema 252 and application health. Preserve all existing backups and protected configuration. After a successful install, ordinary application-only rollback to its recorded `.12`/252 source may qualify under the updater's exact identity, state, schema and backup checks; it preserves database writes. Busy, critical or incomplete recovery states block it. A new install clears the prior rollback record. Post-exposure installation failure suppresses automatic restore even at the same schema. Explicit health/image checks are required after manual rollback. Before rollout, `.12`'s recorded `.11`/251 rollback was blocked; `.13` now records `.12`/252 as its conditional application-only rollback source.
