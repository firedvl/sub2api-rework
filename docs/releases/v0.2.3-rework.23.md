# v0.2.3-rework.23 — Claude routing and quota isolation

Claude Code's Opus 4.6 requests could reach an Antigravity account through a legacy model mapping, even when native Anthropic accounts offered the model. Background Haiku requests had the same problem and could run Sonnet instead. Automatic ownership now includes the native account's discovered model inventory, including supported snapshot aliases. Explicit account allowlists and composite routes keep their precedence. Simple mode prefers the detected native provider when both providers offer the model; ordinary composite groups still require an explicit route for ambiguous ownership.

Anthropic's `Usage credits are required for long context requests.` response uses HTTP 429, but it does not mean that every model on the account has exhausted its quota. The old handler used its billing reset to block all models until December 1. This release keeps short requests eligible and returns an actionable HTTP 400 explaining that the conversation needs compaction or a new chat. Model entitlement failures return HTTP 402 and affect only the named model. They do not enable credits or change billing controls.

The wider check found and fixed these related cases:

- Credits required for non-Fable models also reached the account-wide cooldown path. These now use model-specific keys, with short names, dated aliases and `[1m]` variants resolving consistently.
- A Fable version's credit requirement could block other Fable versions. Credit requirements now stay with that version; the shared Fable weekly quota still covers the family.
- Sonnet and Opus weekly quota headers could reach the shared account limiter. Their deadlines now apply only to their respective families. Fable's existing `7d_oi` handling remains in place.
- A family quota with no usable reset could still fall through to the account limiter. It now uses the configured short backoff for that family. Healthy shared windows use `Retry-After` or the short fallback, instead of an unrelated quota reset several hours away. Confirmed shared quota exhaustion still takes priority.
- A weekly `status=rejected` without a utilization value could select an unrelated, earlier five-hour reset. Rejected status now counts as exhaustion.
- The native Anthropic adapter could apply a temporary model rule before checking a real shared quota, and could lose the requested model during error handling. It now uses the shared Anthropic policy directly.
- An HTML 403 or Cloudflare bot block could permanently disable a healthy native Claude account. These edge failures now retain the account, matching the existing protection for other providers. Structured account-permission failures retain their existing handling.
- A successful request already in flight could clear a newer shared cooldown and independent model limits. Passive five-hour observations no longer clear those limits. An aggregate reset also no longer invents a five-hour session window. Deadlines and explicit recovery keep their existing roles.
- Millisecond reset timestamps could become deadlines in the year 58,845. Per-window and aggregate reset parsing now normalize milliseconds to seconds.
- Responses and Chat Completions could hide credit requirements behind generic exhaustion errors. Messages, Responses, Chat Completions and the native adapter now use the same credit-error classification, with their existing response formats.

| Persistence | Existing account/model update and scheduler-outbox paths are reused; no schema change |
| Console | Existing model-limit rendering accepts the stored scope keys; this release changes no frontend source |
| Release | Repository CI, embedded builds, immutable image/manifest validation and the managed updater remain required |

The new service regressions are in `anthropic_routing_quota_regression_test.go`; protocol coverage is in `anthropic_credits_errors_test.go`. Existing window, recovery, scheduler and streaming tests also cover the changed paths. Production failures supplied the Opus/Haiku routing and long-context evidence. The other failure cases use synthetic local fixtures; no real account was exhausted to trigger them.

The live routing corrections send standard Opus 4.6, Haiku and Sonnet 4.6 requests to native Anthropic. Explicit `ag-*` aliases and the Antigravity-only thinking route remain available for callers that request them.

No database migration or updater binary change is required. Schema remains 252, supported schemas 239–252, minimum updater 1.1.6, stable channel and manual update policy. The `.22` image and the updater's pre-install backup provide the application rollback target. Accounts, credentials, subscriptions, pricing, credit controls and retained backups are outside the release changes.

Long-context access still depends on the upstream subscription. For an affected existing conversation, compact it using a working model before switching to Opus 4.6, or start a new chat. See the [official context configuration](https://code.claude.com/docs/en/model-config#extended-context).
