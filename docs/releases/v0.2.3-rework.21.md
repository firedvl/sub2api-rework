# v0.2.3-rework.21 — Operator console and usage-limit resets

The operator console uses a graphite and iris theme, a page title in the header, and reorganized navigation. Overview shows fleet and usage summaries; Stats separates Usage and Capacity. The header button collapses the sidebar, with Ctrl/Cmd+B as its keyboard shortcut. The sign-in page shows the gateway routing flow.

When every account that can serve a model is blocked until a known reset, the gateway returns `429` with the earliest reset time. Messages includes Anthropic rate-limit headers; Responses and Chat Completions include `usage_limit_reached`, `resets_at`, and `resets_in_seconds`; Gemini native includes `Retry-After`. Claude Code waits and resumes by itself only when the reset is 60 seconds away or less, or when `CLAUDE_CODE_RETRY_WATCHDOG=1` is set. See the [usage-limit contract](../CLAUDE_CODE_ACCOUNTS.md#when-every-account-is-out-of-usage).

The backend caches empty single-Antigravity group probes for five seconds and the usage-log sections of `GET /v1/usage` for 30 seconds per API key and range. Billing uses one API-key update when both quota and rate limits apply. Sticky-session diagnostics use Debug logging.

No database migration or updater binary change is required. Schema remains 252, supported schemas 239–252, minimum updater 1.1.6, stable channel, and manual application-update policy. The separately held forwarding-header and backup-digest security changes are excluded.

Production acceptance will be recorded after qualification and deployment. Usage-limit verification uses synthetic tests; real accounts will not be exhausted to trigger a reset response.
