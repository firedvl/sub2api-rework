# v0.2.3-rework.28 — Codex model discovery acceptance

Release `.28` was installed on November 17, 2026 at 7:59 PM PST through unchanged host updater 1.1.6. The application, PostgreSQL, Redis, public health and updater are healthy. Schema remains 252, with supported range 239–252. No account policy, credential, billing, routing, permission or updater setting was changed by the release.

## What changed and why

Codex needed an explicit native catalog URL to discover GPT-6.2 models from the custom provider. That client-side change is [Agent-Setup PR #100](https://github.com/firedvl/Agent-Setup/pull/100). Gateway acceptance then exposed three latency causes:

- [PR #333](https://github.com/firedvl/sub2api-rework/pull/333), released in `.26`, fetches account manifests concurrently while retaining account precedence and filtering.
- [PR #335](https://github.com/firedvl/sub2api-rework/pull/335), released in `.27`, shares identical raw and client catalog storage. A roughly 894 KB native manifest had been counted twice against the 1 MiB cache budget and therefore rejected from the cache. Client-copy isolation and the memory limit remain intact.
- [PR #336](https://github.com/firedvl/sub2api-rework/pull/336), released in `.28`, shares one account-ownership read across the catalog request. Repeated per-model account reads still exceeded the client deadline after the earlier fixes. Resolver scope, explicit-route precedence, ambiguity handling, authorization, errors and next-request freshness are retained.

The `.26` and `.27` deployments were healthy but did not pass the quiet-period native discovery acceptance. They are not presented as complete latency fixes. A read-only production-data comparison of the real handler measured `.27` at 8.851 seconds on its first request and the `.28` code at 1.202 seconds, returning the same 1,836,202-byte catalog with 56 models.

## Production acceptance

Fresh CLI and desktop client homes returned the full 56-model catalog with `gpt-6.2-sol` and `gpt-6.2-astra` advertised as V2 models. Initial checks took 4.512 seconds for CLI 0.169.1 and 2.864 seconds for the desktop binary. After at least 35 seconds of quiet, fresh client checks took 2.731 and 2.854 seconds. These checks reproduce the condition that previously returned an empty catalog at the five-second deadline. They are measurements, not a latency guarantee for every upstream failure or rollout.

All 11 accounts, credentials, groups, assignments, routes, settings, billing controls and API-key/subscription/quota configuration match the fresh pre-install baseline. All 331,357 historical usage rows through ID 331921 retain their hash. All ten prior backup directories are unchanged. The new readable, checksum-verified `.27` source backup makes eleven; its source image is retained. Runtime reset observations and one automatic credit check timestamp advanced, while control fields stayed unchanged. During the earlier `.27` acceptance interval, one Anthropic account performed normal OAuth token rotation; no credential was manually changed.

A bounded post-install sample of 214 log lines contained no error, fatal or panic records. Strict Agent-Setup configuration/model validation also passed against the live gateway. No new model inference, paid-provider canary, production browser UI interaction, destructive recovery or rollback was required for this deployment acceptance. The running picker UI was not inspected; native model discovery was verified directly through the exact client binaries.

Private hashes, operation receipts, preservation comparisons and probe logs remain outside Git under `.codex/gpt62-catalog-*`. Temporary host probes read credentials only on the host and used read-only database access; they were removed after acceptance.
