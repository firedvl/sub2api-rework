- `245_content_moderation_engine_meta.sql`

## Rollback And Recovery

Do not run .6 against schema249.

Exact `.6` can lose migrated group reasoning-effort billing multipliers on
schema249. Application-only rollback after schema advancement is unsafe.

Before candidate exposure, updater 1.1.5 may automatically restore the verified
pre-update snapshot and exact `.6` at schema244 if migration or install fails.
Once candidate exposure is possible, automatic old-database restore and
automatic `.6` startup are forbidden. A blocking failure leaves the candidate
quiesced and preserves both the current database and the pre-update backup.

After candidate exposure, rollback requires updater 1.1.5 two-stage rescue
recovery back to the recorded schema244 snapshot. Prepare recovery first:
quiesce the application, create and verify a rescue backup of the current
database, and persist its identity and checksum. Then use the updater's explicit
operation-bound confirmation to restore the recorded schema244 database and
exact `.6`. Preserve the rescue backup, including any post-upgrade writes,
after recovery.
