# v0.2.3-rework.8

This Rework release candidate incorporates upstream v0.2.14 at
`0363b8cdba8cec3e2ba4b2dbd49c4481143fa55d`. The reconciliation accounts for
173 commits in 66 clusters. Rework retains its `v0.2.3-rework.N` version lineage
and manual update policy. Preparation does not publish or deploy this candidate.

## Changes

- Native `gpt-6.1-sol` compatibility for low, medium, high, xhigh, and max reasoning,
  with separate legacy GPT-6 Sol, Luna, and Astra identities.
- Provider discovery, account restrictions, group allowlists, and Codex remote
  catalogs preserve the distinction between discovery, routability, and availability.
- Responses, Chat Completions, Messages, streaming, tools, prompt caching, and
  billing retain the Rework Gateway contracts.
- Fresh administrator setup generates private credentials, validates supplied
  passwords, and preserves existing administrators.
- EasyPay callback signatures, order/merchant/amount binding, and transactional
  financial idempotency reject forged and replayed payment callbacks. Legacy
  numeric callback IDs cannot select modern orders with different external IDs.
- TypeSafe provider support and payment recharge bonus accounting.
- Scheduler, routing, authentication, parser, transport, quota, and operator UI
  improvements from the reconciled upstream baseline.

## Database And Installation

Database migration: schema249 -> schema251. Supported starting schemas: 239-251.
Minimum updater: 1.1.6.

Updater 1.1.6 corrects a pre-exposure snapshot timing defect in 1.1.5: source
writers are quiesced and verified stopped before the backup is taken. Writes
acknowledged before shutdown must survive pre-exposure restoration. A failure
before candidate activation recovers the source without restoring an older
database. Existing 1.1.5 installations must upgrade the updater before `.8`;
this preparation does not install it in production.

Historical migration SQL through 249 remains immutable. The upgrade adds:

- `250_add_typesafe_platform.sql`: extend quota and Composite route platform
  constraints while leaving channel-monitor provider constraints unchanged.
- `251_add_payment_order_bonus_amount.sql`: add a non-null bonus amount with a
  zero default for existing orders, and widen pay amount to three decimal places.

Use the qualified source, approved manifest, and immutable OCI digest through
the established updater prepare/install flow after separate publication and
deployment authorization.

## Rollback And Recovery

Application-only rollback to `.7` against schema251 is blocked. Restore `.7`
only against its recorded schema249 snapshot and immutable source image.

Updater 1.1.6 preserves the 1.1.5 `EXPOSURE_POSSIBLE` rules before candidate
launch. After possible exposure, a failure must preserve the current database, quiesce the application,
and enter the required safe state. Automatic database restoration is forbidden.

Explicit recovery requires verified quiescence, a checksum-verified rescue of
the current database, and the operation-bound acknowledgement returned by the
updater. Restore the recorded schema249 snapshot and exact `.7` image while
preserving the schema251 rescue, including post-upgrade writes. Interrupted
recovery must remain deterministic and fail closed.

## Qualification Limits

Provider compatibility and payment behavior use synthetic responses and
disposable infrastructure. Real GPT-6.1 inference, live provider availability,
real payment processors, Reset Credit, referrals, withdrawals, and paid video
generation are not tested. Windows builds are cross-compiled; native Windows
execution is not qualified. Redis Cluster and mixed-version writers are outside
the supported deployment qualification unless separately tested.

The two XLSX high-severity exceptions expire on 2027-01-06 and apply only to the
documented write-only admin export path. Retained unused Go module advisories
and other frontend dependency findings remain documented qualification limits.
